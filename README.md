# 九層技術講義

寫程式與規劃之間有一層技術知識，決定資料該長什麼形狀、東西會怎麼壞、金鑰放在哪裡、排程為什麼跑在錯的時刻。這一層沒有一個動作是打字寫函式，但每一個決定都需要技術知識才做得出來。

這份講義把那一層分成九塊，每塊講四到六個核心觀念。每個觀念的寫法固定成三步：白話說明機制、給一個能自己驗證的例子、再說明它如何改變你的做法。

**線上閱讀**：[index.html](index.html)（單一檔案，無外部相依，直接下載開啟也可以）

## 收錄原則

優先收錄「不懂會安靜出錯」的技術，而不是「不懂會立刻報錯」的技術。

大聲失敗的錯誤自帶學習迴路——你會立刻知道、立刻查、立刻改，一次就學會了。安靜出錯沒有迴路，它會帶著錯的結果一路往前，等到被發現時，中間累積的每一個結論都已經不可信，而且無法回推是哪一步開始錯的。

這條線也用在同一個技術的內部。以排程為例：表達式寫錯會讓任務不跑，你很快就會發現；沒有宣告時區會讓任務照跑，只是跑在錯的時刻，要去對紀錄的時戳才會發現。前者可以現查，後者必須自己懂。

## 九層

| 層 | 主題 | 這一層管什麼 |
|---|---|---|
| L1 | 執行環境與命令列 | 一個指令跑起來時，實際發生了什麼 |
| L2 | 版控的資料模型 | 你的檔案在時間軸上的狀態，以及誰拿得到什麼 |
| L3 | 依賴與環境重現 | 程式跑起來時，它身邊有哪些別人寫的東西 |
| L4 | 關聯資料庫的機制 | 資料該長什麼形狀，以及誰負責把錯的資料擋在門外 |
| L5 | 資料源與網路協定 | 你的系統和外面世界之間的每一次對話 |
| L6 | 程序、排程與並發 | 什麼時候發生、發生幾次、同時發生會怎樣 |
| L7 | 部署與拓撲 | 程式實際跑在哪裡，以及它和其他東西之間的線怎麼接 |
| L8 | 身分、秘密與權限 | 誰碰得到你的東西，以及秘密放在哪裡 |
| L9 | 觀測與除錯 | 怎麼知道它壞了，以及壞了之後怎麼定位 |

層號標示的是「這件事發生在系統的哪個位置」，從最底層的執行環境到最上層的觀測。它不是難度，也不是建議的閱讀順序。

## 讀法

一次讀一層。每層的四個段落分工不同：

- **為什麼學**——缺了這一層會發生什麼具體的事
- **要學什麼**——這一層的題目清單，附英文術語
- **核心觀念**——可以直接吸收的部分。讀完就知道了，不必再去別處查
- **延伸學習方向**——可直接搜尋的英文關鍵字、值得讀的東西、一個動手方向

術語一律附英文，因為延伸學習幾乎只能靠英文關鍵字搜到有用的資料。

讀完一層之後最有效的一步，是把那一層的「動手方向」真的做一次。這一層的知識有個特性：讀過會懂，但只有親手看過它壞掉一次才會變成直覺。並發那一層特別是這樣，因為那類故障在測試時不會發生。

## 邊界

這份講義不收以下題目，理由都是同一條原則——它們錯了會立刻報錯，或在小規模系統碰不到：

- **程式語言、語法與演算法**：屬於撰寫層，錯了會立刻報錯，也查得到。
- **語法細節**（觸發器怎麼寫、排程表達式的每種變體、遞迴查詢怎麼組）：這一層需要的是「該不該用它」的判斷，而那個判斷不需要語法。
- **加密與網路協定的內部原理**：實務上需要的只有一句「加密傳輸不等於不讓人敲門」。
- **容器內部原理與映像分層**：需要的是一張自己畫的拓撲圖，不是建置機制。

兩個目前排除、但條件變了就該補的題目：**前端視覺與樣式**（這類故障幾乎都是大聲失敗，也不影響資料正確性——但如果需要親自判斷介面設計就該補）；**效能調校與索引優化**（小規模系統碰不到那個門檻——但當資料量成長到查詢開始變慢就該補）。

## 技術細節

`index.html` 是一份完整的單一檔案網頁，沒有任何 JavaScript，也不依賴任何外部資源——除了 Google Fonts 提供的三套拉丁字體（Newsreader、Libre Franklin、IBM Plex Mono）。連不到字體時會落回系統字體，內容與版面都不受影響。

中文一律使用系統字體堆疊（PingFang TC、Noto Sans TC、Microsoft JhengHei），標題另外優先採用系統的宋體。這是刻意的選擇：拉丁字體管不到中文字符，載入中文網頁字體的代價又太高。

頁面支援淺色與深色主題，跟隨閱讀者的系統設定。
